# 로그인부터 내 다음 과업까지

포털은 연구 상황을 보는 화면이고, 작업 원본·요청·응답은 GitHub에 있습니다.
**웹 로그인 → 내 계정 확인 → 현재 프로젝트 → 내 요청 원문 → 다음 행동** 순서로 확인하세요.
연구실 초대 전에도 [공개 시작 안내](https://github.com/nii-lab/niil-docs/blob/main/START-HERE.md)로 개인 공간 실습은 할 수 있습니다.

## 1. 포털에 들어가기

1. [NiiL 포털](https://niil-portal.pages.dev/)을 엽니다. Cloudflare Access를 거쳐 GitHub 로그인이 나올 수 있습니다.
2. **nii-lab 초대를 수락한 본인의 GitHub 계정**으로 로그인합니다. 연구실 공용계정이나 다른 사람의 계정을 빌리지 않습니다.
3. 본인이 설정한 2단계 인증을 완료합니다. 포털 대시보드가 나타나는지 확인합니다.
4. 화면 오른쪽 **내 계정**에서 로그인됨을 확인합니다. 로그인 화면·GitHub 홈만 본 것은 포털 진입 완료가 아닙니다.

브라우저 로그인과 agent의 GitHub MCP/CLI 인증은 별개입니다. MCP로 저장소가 읽혀도
그 컴퓨터의 Chrome이 로그인됐다는 뜻은 아닙니다. 다른 기기에서 한 로그인도 이 기기로 옮겨지지 않습니다.
Agent는 연결된 브라우저 조작을 도울 수 있지만 사용자 인증 수단을 대신 생성하지 않습니다.
비밀번호·OTP·Passkey·복구코드·세션쿠키·토큰은 채팅이나 보고서로 전달하지 않습니다.

## 2. 로그인에서 막혔다면

| 실제로 보인 화면 | 먼저 확인할 것 | 다음 행동 |
|---|---|---|
| GitHub 로그인 화면 | 본인 계정/2FA가 필요한 정상 단계인지 | 사용자가 같은 브라우저에서 로그인. Agent는 완료 후 이어감 |
| GitHub에서 `What‽ / Your browser did something unexpected` 또는 `/sessions/two-factor/...`의 404 | 포털 화면이 아니라 GitHub 인증 도중인지 | 아래 ‘GitHub 자체 로그인’ 순서로 한 번 분리 |
| Access의 접근 거부 | GitHub 로그인 성공과 조직 소속은 별개 | 로그인 계정·초대 수락 여부 확인 후 운영자에게 접근 요청. 인증/조직 제한을 풀지 않음 |
| 포털은 보이지만 내 이름/Issue가 없음 | 멤버 로그인과 참여자 등록/개인화 연결은 별개 | 3절의 미연결 분기로 진행 |
| Agent 도구가 `Local browser access is unavailable for this chat` | 웹사이트 오류가 아니라 도구 연결 불가 | 가능한 경우 기존 computer-use의 Chrome 앱 조작 경로 사용. 불가하면 사람이 같은 화면에서 로그인/연결하고 agent에 완료만 알림 |

### GitHub 자체 로그인으로 분리하기

1. 기존 오류 주소를 새로고침하거나 뒤로가기로 계속 재전송하지 않습니다. 새 창에서
   [GitHub 홈으로 돌아오는 로그인](https://github.com/login?return_to=%2F)을 엽니다.
2. 본인 아이디·비밀번호로 새로 로그인합니다. Passkey 경로에서 오류가 났다면 2단계 인증의
   **More options → Authenticator app**처럼 **본인이 이미 설정한 다른 방법**을 선택할 수 있습니다.
   실제 제공되는 방법만 사용하며, 인증 앱 코드도 사용자가 직접 입력합니다.
3. GitHub 홈의 본인 계정 로그인을 확인한 뒤 **같은 창**에서 [포털](https://niil-portal.pages.dev/)을 다시 엽니다.
4. 여전히 같으면 같은 시도를 반복하지 말고, 브라우저 종류·오류 발생 단계·오류 문구·시각만 운영자에게 전달합니다.
   OAuth 주소의 긴 query/state나 화면의 인증정보는 복사하지 않습니다.

2026-11-13 한 실제 사례에서는 일반/시크릿 Chrome 모두 GitHub WebAuthn 오류와 인증 앱 경로404가
관측됐고, 시크릿 창에서 GitHub 자체 로그인을 새로 완료한 뒤 같은 세션의 포털 진입이 성공했습니다.
**근본원인이나 모든 사용자에게 통하는 해결책을 입증한 것은 아닙니다.** 시크릿 창은 분리 진단의 선택지이며
확장 전체 비활성화·2FA 해제·쿠키/인증정보 이동은 이번 복구에 필요하지 않았습니다.
시크릿 창을 모두 닫으면 그 창의 로그인도 사라질 수 있으므로 영구 로그인 설정으로 오해하지 않습니다.
[GitHub 공식 2FA 안내](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/accessing-github-using-two-factor-authentication).

## 3. 지금 연구가 어디에 있는지 확인하기

1. 대시보드의 프로젝트 카드에서 참여할 프로젝트를 엽니다. 학생 화면은 **내 프로젝트 미니맵**, 교수 화면은 **진행 중인 연구**로 표시될 수 있습니다. 보이는 카드는 공유 범위의 요약입니다.
2. 왼쪽의 **현재 연구 흐름**과 선택된 현재 단계를 봅니다. 완료/진행/대기를 구분합니다.
   **이전 연구 흐름**은 당시의 작업·결과이며 새 실행 지시가 아닙니다.
3. 선택한 단계의 결과와 다음 인수를 읽습니다. 모르면 배경·방법과 수치·검사 범위를 펼칩니다.
4. 근거 링크를 새 탭에서 열고 프로젝트 원본의 **현재 상태(current)**와 최신 연결 보고를 확인합니다.
   GitHub Issue의 Open 표시나 오래된 본문만으로 진행 중이라고 판단하지 않습니다.
   수정된 본문·댓글과 guide revision도 확인합니다.

Agent가 쓸 근거는 위 프로젝트와 명시적으로 연결된 공유 자료입니다. 개인 저장소 전체나 다른 연구를
훑어 맥락을 채우지 않습니다. 포털과 원본이 다르면 각 기준 시점과 차이·정확한 URL을 기록합니다.

## 4. 내 다음 과업 확인하기

대시보드로 돌아가 학생 화면의 **내 퀘스트**(교수 화면은 **지금 확인**)에서 본인 대상을 확인합니다. 다른 사람을 선택한 상태라면 본인으로 돌립니다.
프로젝트의 담당 역할과 본인 실제 계정 매핑을 확인하고, agent는 연결 안내의 **inbox(받은 요청)**와
**outbox(보낸 요청)**도 읽어 아직 끝나지 않은 요청을 대조합니다.
[계정·개인 공간과 요청 도구 연결](https://github.com/nii-lab/niil-docs/blob/main/guides/connected-onboarding.md).

| 찾은 상태 | 다음 행동 | 완료했다고 쓰면 안 되는 것 |
|---|---|---|
| 본인에게 유효한 요청이 있음 | 원문의 목적·입력 revision·산출물·완료 기준과 본인 위임/실제 권한을 읽고 수행 또는 필요한 결정 연결 | 화면에서 카드만 본 것을 작업 인수/실행으로 쓰지 않음 |
| 등록/개인화가 미연결 | 공개 참여 접수로 계정·참여 프로젝트·개인 공간 연결 요청. 접근 가능한 프로젝트의 실제 담당 요청은 원문에서 확인 | 빈 목록을 ‘요청 없음’으로 쓰거나 다른 사람 ID로 맞추지 않음 |
| 확인한 범위에 본인 요청 없음 | ‘이 계정/프로젝트/시각의 미완료 요청 없음’으로 기록. 참여할 일이 필요하면 Owner에게 첫 작은 과업·입력·완료 기준을 질문 | 다른 학생 과업을 가져오거나 새 실험·예약을 임의 생성하지 않음 |
| 연구 사이클이 종료됨 | 종료 근거·결과·미검증을 확인. 새 요청이 없는 한 종료 검사를 반복하지 않음 | 시간별 조회를 연구 진행으로 표시하지 않음 |
| 실행은 끝났으나 검토/공용 환류가 남음 | 다음 인수 담당과 필요한 원본/검증을 확인해 전달 | 결과 공유를 Owner 수용·웹 배포 완료로 쓰지 않음 |

연구실 참여 접수는 [공개 접수 안내](https://github.com/nii-lab/niil-docs/blob/main/guides/participation.md)를 사용합니다.
본인 Issue가 없는 새 참여자에게 기존 연구의 완료 과업을 자동 배정하지 않습니다.

## Agent 실습 · 안내만 읽고 여기까지 왔는가

공통 START-HERE와 계약을 읽은 뒤 이 실습을 수행합니다. 원격 게시나 실험은 이 조회 실습의 필수 조건이 아닙니다.
사용자에게 아래 일곱 줄을 짧게 보여주세요. 각 줄에 **확인 / 미확인**과 근거를 적습니다.

```text
웹 로그인: 포털 회원 화면 도착 여부 (인증정보 제외)
Agent GitHub: 실제 login·허용 repository 읽기 여부 (웹 로그인과 별도)
등록/개인화: 본인 identity 연결 확인 또는 미연결·다음 담당
현재 연구: 프로젝트·현재 단계·결론, 원본 URL/revision·확인 시각
내 요청: 계정/프로젝트·request ID/guide revision·상태, 또는 확인 범위의 없음/미확인
다음 행동: 내가 할 일·입력·산출물·완료 기준, 또는 실제 인수 담당/해제 조건
남은 한계: 아직 확인하지 못한 접근·권한·실행과 다음 확인 방법
```

통과는 ‘항상 일이 배정됨’이 아니라 **현재 상태와 다음 행동을 근거로 구분함**입니다.
미연결·요청 없음·종료 상태도 올바르게 진단하면 이 조회 미션을 마칠 수 있습니다.
실제 새 학생 계정의 권한·개인화·게시/응답은 그 계정으로 수행한 뒤에만 passed_live로 남깁니다.
