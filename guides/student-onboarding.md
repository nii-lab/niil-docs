# 학생 온보딩 · 내 공간에서 첫 공유까지

웹 로그인·현재 연구·본인 과업 확인은 [로그인부터 내 다음 과업까지](https://github.com/nii-lab/niil-docs/blob/main/guides/login-and-next-task.md)를 따릅니다.

첫날의 목표는 **내 공간, 기록 하나, 내가 선택한 공유·승인 범위**다.
배경지식이나 조직 초대가 없어도 로컬부터 시작한다. 아래 시간은 작업량의 예시이며
계정 준비·초대·사람의 응답을 기다리는 시간은 포함하지 않는다.

## 0–10분 · 개인 공간과 첫 기록

사용 중인 agent에게 [START-HERE](https://github.com/nii-lab/niil-docs/blob/main/START-HERE.md)를 읽혀 새 폴더를 준비한다.
포털 로그인은 선행 조건이 아니다. 기존 공간이 있으면 새 starter로 덮어쓰지 않는다.
current.md에는 관심 질문·현재 이해·다음 작은 작업을 적고, records/에 첫 기록을 만든다.
실행하지 않은 실험은 결과로 쓰지 않는다.

AI에게: “내 개인 공간과 첫 기록을 만들어줘. 실제 확인과 가정을 구분하고 공유는 기다려줘.”

연구실 연구용 개인 저장소는 **nii-lab 소유의 독립 Private repository**를 기본으로 한다.
교수는 Admin, 담당자는 Write, 나머지 조직 멤버는 Read다. 담당자가 자기 저장소에 직접 기록하며
개인 연구의 매 기록마다 PR을 만들지는 않는다. 혼자만 볼 초안·agent 정책·비밀값은 ignored 로컬
공간에 둔다. Private은 연구실 밖 비공개이며 개인 폴더/visibility만으로 멤버의 열람이 차단되지는 않는다.
Wiki·대시보드는 여전히 명시적으로 공유한 Issue만 집계한다. [저장소·권한 안내](repository-access.md)를 따른다.

## 10–15분 · 내 위임을 선택

매번 확인(manual), 고른 행동만 자동(allowlist), 정한 범위 안에서 자동(auto_within_scope)을
설명받고 본인이 고른다. 발신자·repository·project·행동과 실행 주기를 따로 정한다.
교수나 다른 학생의 설정을 그대로 내 동의로 취급하지 않는다. 정책 파일은 Git에서 제외한다.

AI에게: “각 선택의 차이를 설명해줘. 아직 내가 고르지 않은 항목은 설정 대기로 남겨줘.”

manual이면 공유·답변·승인 대기 댓글의 원격 게시도 먼저 확인한다. 로컬 초안을 만드는 것과
공용 공간에 보내는 것은 별개다. 자동 처리하지 않는 선택도 정상적인 참여 방식이다.

## 15–25분 · 연결과 첫 공유

[실제 연결 안내](https://github.com/nii-lab/niil-docs/blob/main/guides/connected-onboarding.md)에 따라 본인 GitHub login과 numeric ID,
조직 멤버십, private hub Read, project 등록을 확인한다. 초대 대기·등록 누락이면
필요한 login/project만 운영자에게 전달하고 needs_access로 보존한다. 개인 초안은 계속 쓸 수 있다.

공유할 기록 **한 건**을 골라 owner/id/project, version=1, summary/body/next_action,
lab 공개 범위, 고정된 원본 commit과 URL을 확인한다. 개인 원본과 공유 기록을 본인 Git에 보존한다.
기록의 accepted는 공유를 확정했다는 뜻이며 연구 주장을 학술적으로 검증했다는 뜻이 아니다.

AI에게: “이 한 건의 공유 초안을 보여줘. 내 정책과 실제 권한을 확인한 뒤 게시해줘.”

같은 기록을 고치면 같은 Issue에서 version을 올린다. 통신이 끊겼다면 먼저 Issue를 다시 읽는다.
이미 같은 내용이 반영됐으면 재생성하지 않는다. web은 요약이며 개인 원본 전체를 보관하지 않는다.
공동 코드·템플릿·규약을 바꿀 때만 branch/PR을 사용한다. 일반 결과 공유에 fork/PR은 필요 없다.

## 25–30분 · 작은 요청과 다음 세션

목적·공유 입력·원하는 산출물·완료 기준·수신자·guide revision을 갖춘 검토 요청을 준비한다.
수신 agent는 자신의 권한으로 판단한다. 부족하면 본인에게 필요한 결정 한 가지를 묻는다.
수신자는 응답하고 발신자는 근거를 확인해 수용한다. 답변과 수용은 별개다.

AI에게: “요청과 내 위임을 대조해줘. 내가 결정할 것과 바로 할 수 있는 일을 구분해줘.”

Issue 생성이 상대의 Codex/Claude를 즉시 실행시키지는 않는다. 상대가 선택한 수동 확인·예약·
별도 push 연결에 따라 실행된다. 실시간 연결이 없어도 첫 공유와 요청·응답은 가능하다.

완료 보고는 내 폴더, 첫 기록, 공유 Issue 또는 준비된 초안, 위임 선택, 남은 접근/승인과
다음 작업만 보여준다. 전체 시스템이 준비됐다는 단일 완료 표시로 감추지 않는다.

## 한 번 더 연습하기

[Agent tutorial의 세 가지 분기 실습](https://github.com/nii-lab/niil-docs/blob/main/guides/agent-tutorial.md#세-가지-분기-실습)을 본인 상황에 맞게
하나 골라 연습한다. 각 실습은 모의 인물·승인으로 로컬에서 하며 실제 권한을 대신하지 않는다.

| 막힌 상황 | 다음 행동 |
|---|---|
| 가입/초대가 아직 없음 | 로컬 공간·첫 기록을 먼저 만들고 연결은 needs_access |
| manual에서 공유 명령이 거절됨 | 정책을 자동으로 바꾸지 말고 연결 안내의 일회 게시 절차 사용 |
| 복귀 후 다른 계정으로 로그인됨 | 실제 계정을 바로잡은 후 재확인. owner_id를 남의 계정으로 바꾸지 않음 |
| 설치된 client가 수정됨 | 수정본 보존·검토 후 본인이 복원/업데이트 선택. 자동 덮어쓰기 금지 |
| 요청 guide가 바뀜 | 달라진 범위를 읽고 필요한 새 결정 받기. 예전 승인 재사용 금지 |
| Wiki는 바뀌었는데 web은 그대로 | 원본 Issue → Actions Wiki → web 반영 시각을 차례로 확인 |
| 요약이 오래되거나 틀림 | 공유 원본과 source revision 확인. 원본 수정 후 해석 재생성 |

## 첫 주와 졸업·복귀

첫 주에는 동료가 읽을 수 있는 공유 결과 한 건과 재개 가능한 current를 남긴다.
가져온 기록은 출처를 보존한 사본이며 자동으로 내 공유 결과가 되지 않는다.
졸업/이관은 공동 결과·환경·자산·다음 업무를 보존하며 개인 초안 전체 공개를 요구하지 않는다.
복귀하면 기존 기록을 유지한 채 실제 계정·멤버십·등록·개인 정책을 다시 확인한다.
