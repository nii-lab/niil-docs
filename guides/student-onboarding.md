# 학생 온보딩 · 첫 공유까지 30분

이 가이드는 플랫폼 사용과 연구 온보딩을 구분한다. 첫날에는 작은 기록 하나를 공유하고
가져오고 PR을 만드는 흐름을 익힌다. 연구실 전체 운영 문서를 먼저 외울 필요는 없다.

## 0–5분 · 계정과 공간

관리자가 보낸 GitHub Organization 초대를 내 계정으로 수락한다. 개인 연구 repository는
내가 수정하고 동료는 읽는 공간이다. 비공개 초안은 로컬 또는 별도 private repository에 둔다.
공유될 repository에 personal이라는 표지만 붙여 비공개가 됐다고 생각하지 않는다.

AI에게: “AGENTS.md를 읽고 LOCAL.md를 내 계정으로 설정할 항목을 알려줘.
내가 쓸 수 있는 공간과 동료가 읽을 수 있는 공간을 설명해줘.”

## 5–10분 · 내 공간

포털에서 개인 공간 starter ZIP을 내려받아 새 폴더에 푼다. 또는 관리자 제공 도구로 생성한다.
LOCAL.md에 내 owner_id와 승인된 프로젝트를 적는다. AI와 current.md에 목표·다음 작업을 쓴다.
Agent 제품마다 시작 파일 지원이 다르면 첫 프롬프트에서 루트 AGENTS.md를 명시해 읽힌다.
읽지 않는 도구는 짧은 시작 안내 파일로 연결한다. 공통 계약을 여러 파일에 복제하지 않는다.

## 10–15분 · 첫 기록

제공된 작은 예제를 실행하거나 문헌 한 문단을 정리한다. records의 예제 JSON을 새 ID로
만들고 목적·관찰·해석·근거를 채운다. 모르는 것은 미확정으로 남긴다.
AI에게: “이 작업을 기록하고 current를 갱신해줘. 실제로 확인한 것과 제안을 구분해줘.”

## 15–20분 · 공유와 가져오기

AI에게: “이 기록을 연구실 공유용으로 준비해줘. 공유 대상과 첨부파일 접근 범위를 확인해줘.”
대상과 내용을 확인한 뒤 공유한다. 실제 운영에서는 GitHub의 공유된 기록을 포털이 읽는다.
시안의 공유/요청은 내 브라우저 저장에만 반영된다.

동료 기록의 “내 공간으로 가져오기”를 실행하고 내 파생 기록의 새 ID와 derived_from을
확인한다. 같은 bundle을 두 번 import해도 중복되지 않는지 확인한다.
원본 ID가 같은데 내용이 다르면 충돌을 해결한 후 가져온다.

## 20–25분 · 첫 PR

공동 프로젝트를 허용된 계정/조직 안에 private fork한다. 내 fork는 origin, 공동 원본은
upstream으로 설정한다. 작은 문서 개선을 branch에서 작업하고 PR을 작성한다.
AI에게: “승인된 upstream을 확인하고 이 수정의 PR 초안을 준비해줘.
변경 이유·검증·출처를 포함하고 merge는 maintainer 검토 후 진행하게 해줘.”

private fork 메뉴가 없으면 관리자에게 조직 정책을 확인한다. 원본을 public으로 바꾸지 않는다.
main에 직접 push하는 방식과 다른 학생의 공간에 쓰는 방식은 첫 실습 대상이 아니다.

## 25–30분 · 첫 요청과 회신

agent에게 동료의 agent에 보낼 검토 요청을 준비하게 한다. 목적·근거·원하는 산출물·기한·
수신자를 확인한다. 실제 전달은 운영 통신 채널 연결 후 수행한다. 시안에서는 로컬 연습이다.
응답이 오면 근거를 열고 요청을 닫는다. 사람의 결정이 필요한 내용은 대시보드에서 확인한다.

완료: 내 current를 읽어 다른 사람이 현재 목표와 다음 작업을 설명할 수 있고,
동료가 공유한 근거를 열 수 있으며, PR과 요청 ID가 기록에 연결돼 있다.

## 자주 막히는 곳

| 현상 | 확인할 것 |
|---|---|
| 포털에 내 기록이 없음 | 공유 visibility, 등록된 source, 마지막 성공 갱신 시각 |
| 동료가 NAS 파일을 못 읽음 | 링크뿐 아니라 수신 계정의 NAS ACL 확인 |
| 개인 메모가 공개될까 걱정 | 별도 private/local 저장, export 내용 미리보기 |
| AI가 다른 연구원의 요청을 바로 실행 | 내 위임 범위와 요청 목적을 먼저 확인 |
| 같은 기록이 두 개 | stable ID와 derived_from, 중복 import 결과 확인 |
| 요약이 틀림 | 원본을 정정하고 생성 Wiki를 다시 갱신 |
| 연결이 만료됨 | 각 서비스에서 내 계정으로 재인증. 비밀번호를 채팅에 붙이지 않음 |

## 첫 주와 졸업/이관

첫 주에는 대표 결과 한 건을 동료가 재현하고 온보딩 가이드의 막힌 부분을 PR로 제안한다.
연구실은 프로젝트 목표·도구·데이터 접근을 별도로 안내한다. 졸업 전에는 공동 결과·환경·
데이터·NAS 자산을 프로젝트에 보존하고 다음 담당자가 재현한다. 개인 초안 전체 공개를
인수인계 조건으로 삼지 않는다. GitHub 접근 종료 전 private fork의 유지 정책을 확인한다.
