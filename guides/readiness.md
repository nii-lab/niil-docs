# 준비 상태를 부분별로 진단하기

모든 준비를 한 번에 끝낼 필요는 없습니다. 지금 가능한 단계와 다음에 필요한 연결을 구분합니다.
개인 공간과 첫 기록은 로컬에서 시작하고, 공동 기여와 실시간 응답은 접근이 준비된 뒤 확인합니다.

## 읽기 전용 진단

공개 문서 repository의 도구를 사용합니다. Python이 없다면 agent가 아래 항목을 같은 형식으로
직접 확인할 수 있습니다. 진단을 위해 자동 설치·계정 초대·승인 정책 변경을 수행하지 않습니다.

```sh
python3 niil-docs/tools/doctor.py --workspace ./my-niil-workspace --output ./readiness.json
```

본인의 인증·등록 repository 읽기 접근까지 확인하려면 --live-readonly를 추가합니다.
진단 결과에 토큰이나 비밀번호는 포함하지 않습니다. CLI가 없어도 기존 연결 도구를 사용할 수 있습니다.

## 진단 영역과 대응

| 영역 | 확인할 것 | 다음 대응 |
|---|---|---|
| 개인 공간 | current와 새 작업 경로 | starter와 첫 기록 준비 |
| 공통 규약 | 진입 계약·버전 | agent가 읽은 내용과 적용 범위 확인 |
| 개인 위임 | 본인이 선택한 승인·자동 범위 | 필요한 선택만 사용자에게 요청 |
| 개인 정책 보관 | 로컬 정책의 Git 제외 | 실제 추적 여부도 별도 확인 |
| GitHub | 본인 인증·허용 프로젝트 접근 | 초대·권한·계정 연결 확인 |
| 실시간 수신 | 이벤트·인증·cursor 복구 | 중계·개인 연결기·오프라인 경로 확인 |
| Agent 실행 | runner 기동·승인 후 재개 | 개인이 선택한 실행 환경 실습 |
| 튜토리얼 | 미션별 산출물·검증 | 미완료 미션에서 재개 |

ready는 해당 검사를 통과했다는 뜻이며 전체 연구 시스템의 완성을 뜻하지 않습니다.
unknown은 실패가 아니라 아직 검증하지 않은 상태입니다. needs_owner / needs_access /
needs_setup은 각각 사용자 선택·권한·설정이 필요함을 구분합니다.

## 포털에서 보기

포털의 준비 상태 진단 화면에 readiness.json을 선택하면 영역별 상태와 대응을 볼 수 있습니다.
이 파일은 브라우저 안에서만 읽고 서버에 업로드하지 않습니다. 보고서를 다른 사람에게
공유하기 전에는 본인의 프로젝트 이름과 운영 정보가 포함됐는지 확인합니다.

## 지속적인 상태 확인

연결기 등록·권한 변경·agent 교체·장애 후에는 관련 영역을 다시 확인합니다. 정책과 상태의
존재 여부만으로 live 동작을 확인했다고 보고하지 않습니다. 운영자는 실제 수신 지연·오류·
대기 요청·재시도·마지막 성공을 내부 대시보드에서 확인하고 조치를 기록합니다.
