# 결과물 축적부터 미팅 준비까지 · 가상 연습

공통 WORKFLOW.md를 실제 수행으로 익히는 선택적 연습이다. 실제 계정/등록/권한 시험이 아니다.
입력은 [가상 주간 로그](../examples/weekly-workflow/README.md)이며 실제 연구결과로 게시하지 않는다.

## 수행

1. 공통 진입 START-HERE와 templates/common/WORKFLOW.md를 읽는다. 새 연습 공간을 만들거나
   기존 연습 공간의 파일을 보존하며 재개한다. 기존 실제 공간을 initializer로 덮어쓰지 않는다.
2. README의 가상 합의를 current에 연결한다. examples/weekly-workflow/measurements.csv를
   연습 공간 raw/에, summarize.py를 tools/에 복사한다. results/가 있는지 확인한다.
3. 연습 공간에서 `python3 tools/summarize.py`로 실제 로컬 출력을 만든다. 원본 CSV와
   config/코드 revision을 보존한다. Git 로컬 commit은 가능하지만 실제 GitHub push/공유는 하지 않는다.
4. 기존 자동 메모를 근거와 대조해, 합의한 기준에서 무엇을 판단할 수 있는지 설명한다.
   추가 실험 없이 기존 입력으로 가능한 최소 보완을 수행한다.
5. 같은 결과를 반복 보고하지 말고 기존 current/결과 설명과 records/공유 초안을 연결한다.
   실제 URL/push가 없으면 미게시다. 가상 source 좌표는 simulation으로 표시한다.
6. 미팅 준비 초안에 근거/변화/질문/다음 제안을 담고 학생 확인은 대기로 남긴다.
   실제 학생 응답이나 미팅을 꾸며내지 않는다. 부족한 결과와 미팅 준비 부족을 구분한다.
7. Wiki/dashboard 인수를 준비하되 실제 공유 Issue·생성 revision·웹 snapshot이 없으면
   각 단계를 미확인/미수행으로 보고한다. 개인 agent가 중앙 배포를 수행하지 않는다.

## 자기 점검

- 결과만으로 선택을 단정했는가, 원본 분모/누락과 합의한 두 기준을 확인했는가?
- 실제 산출물과 설명/근거가 연결됐는가? 부정적 결과도 보존했는가?
- agent 수행/학생 확인, 로컬 commit/push, 공유/집계/웹 반영을 구분했는가?
- 근거 부족을 구체적으로 설명하고 기존 출력으로 가능한 보완부터 했는가?
- 불필요한 새 실험·별도 일일 보고·협업 할당량·새 승인 단계를 만들지 않았는가?

연습의 반복 횟수는 업적/준비 완료를 자동 증명하지 않는다. Live 환류는 실제 승인된
계정/공유 입력/집계/웹 경로에서 별도로 확인한다.
