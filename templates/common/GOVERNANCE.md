# NiiL 위임·보고·오버라이드 · v0.1

공통 운영안이다. 사람의 역할과 위임은 실제 project 설정과 인증 권한으로 확정한다.
agent는 사람에게 위임된 범위 안에서 실행한다. 모델의 능력이나 역할 선언만으로 승인권이
생기지 않는다. 승인자는 결과·근거·영향에 책임을 지며 agent의 실행과 사람의 수용을 구분한다.

## 개인이 정하는 agent 정책

각자는 자신의 agent의 자동 실행 범위·승인 방식·알림·가용 시간을 정한다. 아래 L0~L3는
공동 프로젝트가 채택할 수 있는 책임 배치 예시다. 개인 agent의 승인 구조를 일률적으로
강제하지 않는다. 자신의 agent 정책으로 타인의 자산이나 공동 원본의 권한을 확대할 수는 없다.

## 의견 게시와 결과 수용의 구분

통상적인 Issue/댓글의 문안·게시 시점은 기존 공유/게시 위임 범위 안에서 작성자가 결정한다.
상시 승인된 소통에 관리자의 사전 문안 승인 단계를 만들지 않는다. 학생 책임자나 PI의 결과
수용·자원/실행 결정권은 다른 참여자의 질문·반론·오류 지적을 허락하는 권한이 아니다.
독자 배려는 이해·판단 비용을 줄이는 것이며 선호할 결론을 추측해 내용을 왜곡하는 일이 아니다.
게시 후 잘못을 발견하면 적극적으로 지적하고 후속 정정·본문의 최신 요약을 연결한다.
각자의 agent 위임 선택과 실제 접근/공유 범위는 유지한다.

## 결정권의 배치 예시

| 수준 | 사람 | 기본 위임 |
|---|---|---|
| L0 | 작업 담당 학생 | 개인 작업 계획·구현·정리·로컬 검증·공유 기록의 정확성 확인 |
| L1 | 지정된 학생 검토자 | 공동 PR의 독립 검토, 재현·방법·근거 확인 |
| L2 | 지정된 학생 프로젝트 책임자 | 승인된 목표 안의 분담·일정·방법 조정, PR 통합, 내부 산출물 수용 |
| L3 | 교수/PI | 연구 목적·대외 주장·공개·권한·위임 정책, 배정 한도 밖 자원, 분쟁·예외·override |

L0 기록 정리는 건별 승인하지 않는다. 공동 변경은 L1 검토 후 L2가 통합한다.
작은 문서 오탈자·명확한 비과학적 정리처럼 프로젝트가 사전 지정한 저위험 범주는
check 통과 후 위임된 maintainer가 통합할 수 있다. 연구 의미·결과·평가가 바뀌면 이 범주가 아니다.
L1과 L2는 작은 팀에서 같은 학생이 맡아도 되지만 자신의 공동 변경을 독립 검토했다고
표시하지 않는다. 다른 검토자가 없으면 지정 대체 검토자 또는 PI에게 해당 변경만 올린다.
PI가 모든 PR의 기본 검토자가 되지 않도록 프로젝트 시작에 대체 검토자를 정한다.

## 위임 설정

project LOCAL.md와 governance.json에 accountable_owner, maintainers, reviewers,
delegated_actions, resource_budget, delegation_valid_until, reporting, escalation을 둔다.
금액·GPU·외부 서비스 한도는 사용자가 실제 수치로 배정한 뒤 실행한다. 미설정/null은
무제한을 뜻하지 않으며 새 지출·자원 예약의 자동 승인을 허용하지 않는다.
새 위임·재위임은 위임자, 수임자, 범위·조건, 만료/재검토 시점, 보고 경로를 기록한다.
단기 대체는 지정 범위와 기간 안에서 책임자가 정하고 기록하며 범위 확대는 PI가 정한다.

## 학생 책임자가 승인할 수 있는 것

- 합의된 연구 목표·완료 기준 안의 작업 분담과 실행 순서 조정.
- 사전 설정된 일정 여유·자원 한도 안의 재실행과 방법 구현 개선.
- 독립 검토와 필요한 check가 있는 공동 PR 통합.
- 연구실/프로젝트 audience 안의 자료 공유와 내부 Wiki 정정.
- 마일스톤 산출물의 기능·재현·증거 수용. 논문용 최종 주장 채택은 PI의 대외 검토 범위와 구분.

## PI에 올릴 것

- 연구 목적·기여/요구 기능·완료 기준의 실질적 변경.
- 평가 타당성·데이터 사용 권한·재현성·중요 오류 때문에 기존 결론을 유지하기 어려운 경우.
- 논문 제출·외부 공개·대외 주장 확정, 연구실 자산 공개 범위 확대.
- 배정 예산·연산·기한 여유를 넘는 약속, 다른 프로젝트에 영향을 주는 자원 충돌.
- 역할·접근 권한·위임 범위 확대, 저자·기여 분쟁, 학생 책임자 판단의 이해 충돌.
- 결론 채택에 영향이 있는 검토 의견 불일치 또는 책임자 없이 멈춘 승인.

위 목록은 모든 실험 실패를 PI에게 올리라는 의미가 아니다. 정상적인 실패·진단은
학생 책임자가 처리한다. 합의된 목표와 계획을 유지할 수 없거나 다른 사람의 권한·자원을
바꿔야 할 때 선택지와 추천을 포함해 상향한다. 응답 대기는 원래 권한 안의 독립 작업을
계속할 수 있다. 대기 중인 결정 자체를 승인됐다고 간주하지 않는다.

## 보고

- 포털은 하루 1~2회 L0~L2 활동과 결정의 요약·근거·다음 마일스톤을 PI에게 보여준다.
- 일상 성공마다 개별 알림을 보내지 않는다. PI 결정 필요, 권한/자원 충돌, 중요한 결론
  정정, 승인 지연으로 마일스톤 영향이 발생한 경우에는 즉시 같은 thread로 올린다.
- 결정 요청은 목적, 관찰된 사실, 선택지, 추천, 영향, 기한, 결정권자, 근거 링크를 담는다.
- 진행 보고의 기준은 commit 수나 agent 대화량보다 얻은 결과·줄어든 불확실성이다.

## 오버라이드

PI는 어느 단계의 위임 결정도 사유와 적용 범위를 남겨 변경·보류·취소할 수 있다.
원래 결정·작성자·근거는 보존하고 새 decision_id에서 supersedes를 연결한다.
PI가 변경·보류한 범위는 하위 승인으로 덮어쓰지 않고 PI의 위임 재개 또는 수정된 범위를
확인한 뒤 이어간다. 재개 결정도 기존 이력과 연결한다.
급히 멈춰야 할 실행은 영향받는 작업만 hold로 전환하고 유효한 결과·다른 실행은 보존한다.
코드·데이터를 되돌려야 하면 별도 revert PR/버전 작업으로 수행한다. 결정 상태 변경만으로
이미 게시된 결과가 실제로 철회·복구됐다고 보고하지 않는다.

이의가 있는 학생은 같은 decision thread에 반증·영향·대안을 남긴다. PI 또는 지정
대체 결정권자가 재검토한다. 이전 결정을 지우거나 새 대화로 감추지 않는다.
교수 부재 시에도 만료되지 않은 위임 범위의 작업은 계속한다. PI 전속 결정은 사전 지정된
대체자에게만 위임하며 무응답을 자동 승인으로 처리하지 않는다.

## 시스템 적용

운영 서버가 인증 actor, 위임 범위·기간, 대상 project, 독립 검토, version과 결정을 검증한다.
GitHub 역할·ruleset과 NAS ACL도 이 범위에 맞춘다. 포털의 역할 드롭다운이나 AGENTS.md는
실제 보안 경계가 아니다. 시안의 승인·override는 브라우저 로컬 실습이며 운영 권한을 바꾸지 않는다.
