# 독자 관점의 보고 피드백

작성자 agent는 제출 전에 아래 질문으로 초안을 고친다. 별도 점수표·인증 댓글을 제출하지 않는다.

| 독자의 질문 | 기본 통과 기준 |
| --- | --- |
| 무엇이 달라졌고 왜 지금 읽어야 하나? | 제목과 첫 요약에 변화·목표 영향·내 행동이 보인다. |
| 이 정보를 어디에 쓸 수 있나? | 다음 판단/작업/다른 모듈의 입력과 연결된다. 정보만 쌓지 않는다. |
| 믿어도 되는 범위는 어디까지인가? | 사실·해석·권고, 보고·검토·승인을 구분하고 주장에 근거가 있다. |
| 연구 전체의 어디쯤인가? | 중간목표와 남은 불확실성, 다음 판정 조건이 보인다. |
| 누가 무엇을 해야 하나? | 담당자·이유·산출물·완료 기준이 있다. 요청이 없으면 없다고 쓴다. |
| 상세를 쓰려면 무엇을 열어야 하나? | 근거·revision·사용 조건을 이름 있는 링크로 찾을 수 있다. |
| 읽는 수고를 줄였나? | 같은 설명을 반복하지 않고 요약→판단 근거→재현 상세 순서다. |

막히는 항목은 무조건 빈칸을 채우지 말고 “미확인, 판단에 주는 영향, 확인 방법”을 표시한다.
문장이 매끄러워도 근거가 없으면 통과하지 못한다. 위 질문은 연구 타당성의 자동 판정이나 학생 평가 점수가 아니다.

## Owner의 짧은 피드백 — 실제 검토 시 필요한 항목만

- **유용했던 점:** [어떤 설명 덕분에 어떤 판단/재사용이 가능했는가]
- **가장 먼저 고칠 점:** [독자가 어디에서 막혔으며 왜 문제인가. 막힌 점이 없다면 수정 요구 없음]
- **다음 수정 행동:** [한 가지 구체적인 변화. 표현 개선인지 추가 근거/실험이 필요한지 구분]
- **내용 판정:** [수용한 범위 / 미확정 / 수정·추가 검증 필요. 글쓰기 조언과 구분]

작성자는 다음 의미 있는 보고/본문 정정에 반영한다. 조언을 받았다는 확인용 댓글은 만들지 않는다.
반복 문제는 같은 Issue나 기존 회고에 “읽기 문제 → 수정 → 다음 보고에서 효과”로 짧게 남긴다.
양식 문제라면 근거 예시를 익명·비공개 범위에 맞춰 PR로 개선하고, 실제 독자의 왕복 질문이나 재사용
성공 여부로 효과를 확인한다. 문장 길이·항목 수·점수 경쟁으로 최적화하지 않는다.
